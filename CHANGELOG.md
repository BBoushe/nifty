# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed
- **Builders use ponytail (Decision 3.15):** `spec-builder` and `spec-implementer` write code with the `ponytail:ponytail` skill and install the plugin when it is missing. `.claude/settings.json` declares the `DietrichGebert/ponytail` marketplace and enables `ponytail@ponytail`.
- **Five-service convergence (Decisions 1.18–1.21, 2.21–2.25):** one contract for the five teammate services: 7 backend slices, UUID keys, shared events, professor routes under `/api/v1/ranking/**`, one-shot immutable assessments, question-only weights and grouping modes. The context builder keeps two separate contexts per attempt, and the evaluator returns machine-parsable levels only. Team formation uses a seeded Simulated Annealing optimizer: Timefold is removed from the build. New `context-creation` spec, five teammate changes and `docs/tickets/`. `docs/artifacts/` and `docs/pdfs/` are now gitignored.
- **Nov 24 follow-ups (Decisions 2.20, 4.5, 1.15):** answers submitted at timeout are now evaluated, and only a question without answer text is `N/A`. There is no cost limit per interview. The `REVIEWER` role is gone from the code: `/api/v1/ranking/**` allows only `PROFESSOR`, and `/api/v1/assessment/**` allows only `CANDIDATE` (`RoleAccessTest`).

### Added
- **Backend foundation (`backend-foundation`):** Spring tests now run on PostgreSQL Testcontainers through `PostgresContainerBase`, and H2 is gone from the tests. The pom uses `spring-boot-starter-webmvc`, and `application.yml` uses `spring.ai.openai.chat.model`. `FieldValidationException` gives `400` with `errors[]`. `AttemptCompletedEvent` and `AssessmentDeletedEvent` are in `shared/config`. All shared interfaces, records and enums of the contract pack §3 exist as stubs, each interface with one placeholder `@Service`. The GitLab `backend` job runs `docker:dind` for Testcontainers.
- **Nov 24 reconciliation (Decisions 1.11–1.17, 2.10–2.19, 3.12–3.14, 4.1–4.4):** O1–O7 are resolved. Specs now cover threshold-gated release, (question, skill) confidence, question-weighted coverage, attempt limits, min/max timers, the append-only conversation ledger with streamed replies, rubric-blind interviewer, invite-link sign-in (new `auth-access` spec) and an optional BFI-10 step. New: `docs/ai_logs/`, the domain model in `docs/architecture.md`, and a backlog of stories in delivery waves with reserved migrations. The 2026-11-22 discovery canvas is archived in `docs/archive/`.
- **Orchestrated delivery (Decision 3.11):** the `orchestrate-changes` skill runs several changes from one session (builder agents in `../nifty-<change>` worktrees, a cold reviewer per PR, PR/MR handling by branch, a user question with an architecture summary before every merge). `node scripts/forge.mjs prs` shows GitHub PRs and GitLab MRs side by side by branch, and `forge.mjs` now reads the main checkout's `.env` from a worktree.
- **Frontend foundation (US-FF-01..04):** the frontend has Vitest (`npm run test`, also a step in both CI files). It has design tokens as Tailwind `@theme` variables and one PrimeVue preset. A new `ScoreBadge` shows `N/A` as a hatched badge and never as `0`. Each feature folder in `views/` (`auth`, `studio`, `assessment`, `ranking`, `teams`) has one `routes.ts`. `src/api/client.ts` parses RFC 9457 errors (`ApiProblem`) and reads SSE streams from a `POST`. PrimeVue 4.5.5 (MIT) is in use because PrimeVue 5 needs a license key.

### Changed
- **Docs in ASD-STE100 (Decision 3.5):** the agent entry points, `.agents/rules/`, README, setup, workflow, architecture, API, design-system and discovery-canvas docs, and the Purpose paragraphs of the 7 domain specs now use Simplified Technical English. Obligation keywords, numbers, paths, commands, REQ IDs and every EARS statement are unchanged (checked per file).

### Fixed
- **Bash guard gaps (post-merge review of PR #7):** the guard now finds `-c` after other shell options (`bash -euo pipefail -c …`) and in `dash`/`ksh`, attached or `=` command strings (`env --split-string=…`, `rtk run -c"…"`), abbreviated `--no-verify`/`--force*`, `-fu`, `+` refspecs, `HEAD`/`@` destinations, `git -c core.hooksPath=…`, commands after `&`, in `( … )`, `{ …; }`, `if`/`while`, `$( … )` and behind `exec`/`timeout`/`nohup`, add/commit chaining through command strings, pipes into a bare shell, and globs that match a secret env file.

### Changed
- **PR-only `dev` (Decision 3.10):** every change, including `docs:` and `hotfix:` commits, now reaches `dev` through a PR, matching the GitHub `dev` ruleset. The harness upgrade board records the outcome and lessons, and the archived F1–F5 `tasks.md` Status blocks show the merges.
